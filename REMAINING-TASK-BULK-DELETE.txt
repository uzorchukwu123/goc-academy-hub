BULK-DELETE FEATURE — WHAT WAS DONE THIS PASS, AND WHAT IS STILL LEFT
=======================================================================

DONE IN THIS PASS (backend only):

1. server/server.js
   - Added: DELETE /api/questions/bulk
     - need: 'console' (same admin/console auth as every other question route)
     - Body: { subject, section } where either/both may be the literal string "all"
     - Rejects missing/blank subject or section (does NOT default to "all")
     - Subject must exactly match an entry in core.ALL_SUBJECTS (after trim),
       unless subject === "all"
     - Section is normalized with core.csvSection() (the same normalization
       already used by the CSV importer), unless section === "all"
     - Computes deleted count and remaining count, persists with the existing
       writeData(db) mechanism, and only writes to disk if deleted > 0
     - Returns { ok, deleted, remaining, subject, section }
   - Route was placed directly after the existing single-question
     DELETE /api/questions/:id route. Individual question deletion is
     untouched and still requires the question to be inactive first.

2. js/goc-core.js
   - Exported the existing internal csvSection() helper as core.csvSection
     so the server route (and the client helper below) reuse the exact same
     section-normalization rules as CSV import, instead of a second
     hand-rolled normalizer.

3. js/api.js
   - Added a client helper, alongside the other question-management calls:
       bulkDeleteQuestions: function (subject, section) {
         return req('DELETE', '/questions/bulk', { subject, section });
       }
   - Pass the literal string "all" for either argument to mean "every
     subject" / "every section" (matches server contract). Resolves to
     { ok, deleted, remaining, subject, section } or rejects with the
     server's error message (existing req() error handling, unchanged).
   - Confirmed the server's readBody() is called for every HTTP method
     (including DELETE) before the route handler runs, so a JSON body on
     DELETE /questions/bulk is parsed correctly — no server change needed
     for this.

UPDATE 2026-09-18 — "Please wait…" HANG FIXED
=============================================
Symptom: "Delete matching questions" stayed on "Please wait…" forever.
Cause: bulkDeleteQuestions existed on the http driver only. The GOC.api
facade (what js/app.js calls) did not forward it, so the click threw
"not a function" after busy(btn, true), and the old .then(ok, fail) had no
catch for errors thrown inside the success step.
Fixed in:
  - js/api.js   : GOC.api.bulkDeleteQuestions forwarder + mock-driver version
  - js/app.js   : admQBulkDeleteByFilter uses .then().catch() so the button
                  always resets
  - sw.js       : CACHE bumped goc-v30 -> goc-v31 so browsers drop old JS
  - test/test-server.js : 4.7b now counts Chemistry/objective before the
                  delete instead of hard-coding 2, and asserts "remaining"
Ran: test-server 396/396, test-persist 20/20, test-driver-parity 8/8.
Still not done: full `npm test`, a real-browser click-through, and the
B-list tests (restart persistence, subject+all, all+section, full clear).
