G.O.C ACADEMY HUB — TEST SUITE FIX STATUS
============================================
Date: 2026-09-14
Context: The test suite was failing because several test files assumed a
hardcoded "demo" student roster (e.g. Scholar ID GOC-S-002 / password
"bello#88", Amara/GOC-S-001, Chidi, etc.) that no longer exists in the app.
The app was deliberately changed to ship with NO seeded demo accounts (see
test-launch.js, which explicitly checks that no demo roster is hard-coded).
The older test files were never updated to match, so they crashed trying to
log in as students that don't exist.

The fix, file by file, is to register a REAL student on the fly through the
same public sign-up path (GOC.api.createStudent with the real access code
"GOC-2027") instead of assuming a pre-seeded account, then use the ID the
driver actually assigns.

============================================
1. REAL BUG FOUND AND FIXED (not a test issue)
============================================
File: js/api.js (mock driver)

While fixing the tests, a genuine production bug was uncovered: the
in-memory state variables `attempts`, `aSeq`, and `openAttempts` were being
USED throughout the mock driver (student test submissions, marking, etc.)
but were never DECLARED/initialized. This means that in the shipped app,
the very first time any real student tried to sit or submit a test, the
app would have thrown a ReferenceError and crashed. This was not caused by
the test changes — it was already broken before I touched anything, and the
test suite is what surfaced it.

Fix applied: added the missing declarations
    var attempts = [];
    var aSeq = 0;
    var openAttempts = {};
near the other seed/state variables in the mock driver, matching the
existing pattern for `questions`, `notes`, etc.

This fix is REQUIRED for the app to work at all for real students, not
just for the tests to pass. It should be treated as the most important
change in this update.
