# Tutor analytics: private Appwrite ledger

The opt-in tutor ledger stores practice history, server-marked answer-counter events and tutor-view audit entries in the private `goc_academy/tutorledger` collection. Records are append-only; separate application instances do not replace one another's data. Browser practice uploads are retried using the same record. Web-test counter events are included only when the corresponding saved attempt exists.

The collection is server-key-only: no public collection permissions and document security disabled. The application refuses to start with the ledger enabled if privacy or the migration receipt cannot be verified. Tutors still use the existing subject and student guards; opening a student or contact requires a successful audit write before data is returned.

## Safe cutover

This feature is **off by default**. Do not enable it on production until the following have been coordinated and approved. Running these steps changes Appwrite data and requires the appropriate Appwrite API-key scopes; this repository does not perform them automatically.

1. Identify and securely preserve a complete, authoritative `data.json` backup. The old whole-file mirror can be stale or incomplete, particularly across multiple instances. Reconcile any differing copies before choosing one. Existing baseline answer counters may already include answers from the retired test; their original sources cannot be separated from the aggregate.
2. Provision the collection and indexes using `node server/setup-appwrite.js`. This script is additive and checks that an existing `tutorledger` collection is private; it does not fix or overwrite unsafe permissions. Wait until the attributes and indexes are available. Provisioning also checks/creates the existing collections and attributes described in that script.
3. Coordinate a period with **all legacy writers stopped** before the final snapshot, import, and switch of every application instance. Otherwise writes made to the old local or mirrored files during migration will not be present in the ledger. Do not change maintenance settings without separate authorization.
4. On the same complete frozen backup, first run `node server/migrate-tutor-ledger.js /secure/path/data.json` for validation, then run the same command with `--apply`. The import preserves the source and never deletes existing records. A migration claim binds retries to the exact same backup bytes; an interrupted import must be resumed with that file. A completion receipt is written only after all records have been acknowledged. Do not print or share the backup or credentials.
5. Verify the imported practice, counter and audit records against the snapshot using privacy-preserving checks, including a test account. Deploy the same code and set `APPWRITE_TUTOR_LEDGER=1` on **all** serving instances together. If the flag is set and the collection or completed migration cannot be verified, startup fails closed. Do not switch an instance back to legacy storage after new ledger writes: the old files will not contain those writes.
6. Verify new practice history, answer counters and tutor views across a fresh instance or restart; test a write failure and confirm student/contact details are withheld if the audit cannot be saved. Only then resume normal traffic.

The tutor and management views show audit entries from the last year. The ledger does not automatically delete older records: a separate, explicitly authorized retention/deletion policy is required. Practice views apply the existing history-age rule, but the underlying ledger records are not deleted. Other academy data still uses its existing storage paths; this change does not fix the whole-file backup's independent consistency limitations.
