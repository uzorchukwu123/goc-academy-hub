ITEM 2 — "GOC Materials" tab in the Resources panel doesn't work
-------------------------------------------------------------------------
This is the real bug, and it took a full reproduction (simulated admin
login -> unlock console -> open Resources -> click "GOC Materials") to
confirm. It is NOT in the student-facing filter chip logic
(renderResources() in js/app.js) — that part was tested in isolation and
works correctly. The bug is entirely upstream, in the admin console.

ROOT CAUSE:
admOpen(section) builds one big object literal, `V`, containing the HTML
template strings for every admin panel (overview, students, cohorts,
questions, topics, league, videos, resources, homepage, classes, results,
theorymark, objective, window, notes, access) — then only uses `V[section]`.

The problem: a JS object literal evaluates every one of its property
values immediately, in source order, the moment the object is
constructed — even though only one property is ever read afterwards.
So every single time admOpen() runs, ALL of those template strings are
built, not just the one being displayed.

Several of those panels call `subjSeg()` with no argument (Questions,
Topics, Live classes). subjSeg() contains this guard:

    function subjSeg(includeMaterials){
      if(!includeMaterials && admSubj === 'GOC Materials') admSubj = 'Physics';
      ...
    }

This guard is meant to protect panels that dropped the "GOC Materials"
tab from getting stuck on it. But because ALL panels' templates run on
every admOpen() call, this guard fires and silently resets the *global*
admSubj variable even when the admin never actually navigated to
Questions/Topics/Classes.

Sequence that breaks it, step by step:
  1. Admin is on the Resources panel, clicks the "GOC Materials" segment.
  2. admSetSubj('GOC Materials') runs: sets admSubj = 'GOC Materials',
     then calls admOpen('resources').
  3. Inside admOpen, the V object literal is constructed top to bottom.
     The `questions:` property (which appears before `resources:` in the
     object) calls plain subjSeg() as part of building its string — even
     though we are not viewing the Questions panel. Because admSubj is
     currently 'GOC Materials' and this call passes no argument, the
     guard fires: admSubj gets reset to 'Physics'.
     (`topics:` and `classes:` do the same thing, redundantly.)
  4. By the time the `resources:` property's own subjSeg(true) call
     finally runs later in the same object literal, admSubj has already
     been stomped back to 'Physics'.
  5. The panel renders with "Physics" selected instead of "GOC Materials"
     — the tab appears to un-select itself. Worse, if the admin doesn't
     notice and uploads a resource anyway, admUploadResource() sends
     `subject: admSubj`, i.e. 'Physics', not 'GOC Materials' — so the
     resource is filed under the wrong subject and will never appear
     under the student's "GOC Materials" filter chip.

This was confirmed with a live simulation, not just by reading the code:
after calling admSetSubj('GOC Materials') from a Resources panel, admSubj
read back as 'Physics' and the "GOC Materials" button rendered without
its "on" class.

THE FIX (not yet applied):
Stop building all panels eagerly. Convert the `V` object literal in
admOpen() into something lazy, so only the requested section's template
— and only that template's own subjSeg() call — ever runs. Two
reasonable ways to do this:

  (a) Turn V into an object of FUNCTIONS instead of strings, e.g.
          var V = {
            overview: function(){ return '<div>...'+ ... ; },
            resources: function(){ return '...'+ subjSeg(true) + ...; },
            ...
          };
          p.innerHTML = (V[section] || V.overview)();
      This is the smaller structural change and keeps the existing
      layout of the code mostly intact — every `key: '...'+...` becomes
      `key: function(){ return '...'+...; },`.

  (b) Refactor to a switch/if-chain on `section` that only builds and
      returns the one template needed. More invasive, but avoids the
      function-wrapper boilerplate.

Either approach removes the cross-panel side effect completely, since
subjSeg() will then only be called for the panel actually being shown.

After the fix, re-run the same reproduction to confirm:
  1. Log in as management, unlock console.
  2. admOpen('resources')
  3. admSetSubj('GOC Materials')
  4. Check admSubj === 'GOC Materials' (should now hold, not reset).
  5. Check the "GOC Materials" segment button has class "on" in the
     rendered panel HTML.
  6. Upload a test resource and confirm it is stored with

     FormData, or by checking admRenderResources()'s output afterward).
  7. Publish it, then confirm it shows up under the student Resources

     renderResources()).
